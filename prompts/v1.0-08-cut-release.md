# Task v1.0-08: Cut the 1.0.0 release

## Context

Read `CLAUDE.md` fully, `docs/RELEASING.md` (the Trusted-Publishing flow),
`pyproject.toml`, `CHANGELOG.md`, and `.github/workflows/` (`test.yml` and any
`publish.yml`). Confirm **v1.0-01 through v1.0-06 have all merged** and the
default branch is green. This is the **last** task — do not start it until the
blocking path is complete.

## Why this task exists

Everything up to here made the code 1.0-worthy. This task performs the actual
version cut: the number, the changelog, the tag, and a verified publish path.

## Pre-flight gate (stop if any fails)

Before touching the version, verify on the merged default branch:

- `ruff format --check .` · `ruff check .` · `mypy mayaastrolib/` all clean.
- `pytest --cov=mayaastrolib --cov-fail-under=80` green (report the real number
  — the project has been ~95%; do not let it regress).
- `python -m build` produces an sdist + wheel; `twine check dist/*` passes; the
  wheel contains only `mayaastrolib` (no `flatlib`).
- No symbol still emits a "removed in version 1.0" `DeprecationWarning`
  (`grep -rn "version 1.0" mayaastrolib/` is clean of removal warnings).
- `docs/API-STABILITY.md` exists and the public-API tests pass.

If any gate fails, **stop** and fix in the appropriate earlier task's follow-up
— do not paper over it in the release commit.

## Design decisions (already made)

- **Version → `1.0.0`** in `pyproject.toml` (single source of truth via
  `importlib.metadata`).
- **`CHANGELOG.md` gets a dated `## [1.0.0]` section** that consolidates:
  the "Removed (BREAKING)" list from v1.0-02 and v1.0-03 (every removed symbol +
  its replacement), the completed type-hint pass, the frozen public API +
  `API-STABILITY.md`, and the docs/Sphinx addition. Lead with a short "Migrating
  from 0.x to 1.0" paragraph pointing at `API-STABILITY.md`.
- **Follow `docs/RELEASING.md` exactly** for the tag + GitHub release + Trusted
  Publishing. Do **not** introduce or store a PyPI token — Trusted Publishing
  (OIDC) is the only standing path.
- **The release itself (tag push / GitHub release creation) is a human action.**
  This task prepares everything and *documents the exact commands*; it does not
  auto-publish to PyPI. The maintainer runs the final `git push origin vX.Y.Z`
  / release-create step after reviewing.

## Task scope

1. Bump `version = "1.0.0"` in `pyproject.toml`.
2. Write the `## [1.0.0]` CHANGELOG section (breaking list + migration lead-in).
3. Verify the packaging metadata is release-ready: classifiers (drop any
   `Development Status :: 3 - Alpha` → `5 - Production/Stable`), `Requires-Python
   >=3.10`, project URLs (repo, docs, changelog), long-description = README.
4. Confirm/adjust `.github/workflows/publish.yml` matches `docs/RELEASING.md`
   (builds, `twine check`, the "wheel computes a real chart" smoke step,
   OIDC publish on release). If `publish.yml` doesn't exist yet, add it per the
   RELEASING doc.
5. Update `docs/RELEASING.md` with anything learned; leave a checklist the
   maintainer can tick to actually push the tag.

## Tests

- The full pre-flight gate above passes on the release branch.
- `python -m build && twine check dist/*` clean.
- A fresh-venv install of the built wheel can compute a chart:
  `pip install dist/*.whl && python -c "from mayaastrolib.chart import Chart;
  from mayaastrolib.datetime import Datetime; from mayaastrolib.geopos import
  GeoPos; from mayaastrolib import const;
  print(Chart(Datetime('2015/03/13','17:00','+00:00'),
  GeoPos('38n32','8w54')).get(const.SUN))"` prints a Sun in Pisces.
- `importlib.metadata.version("mayaastrolib") == "1.0.0"` after install.

## Out of scope

- Actually pushing the tag / creating the GitHub release / publishing to PyPI —
  that is the maintainer's reviewed final step (commands documented, not run).
- Storing any PyPI credential anywhere.
- Post-1.0 feature work.

## Process

Branch `v1.0-08-cut-release`. Commits:
`release: bump version to 1.0.0`,
`docs: write 1.0.0 CHANGELOG with breaking-change migration guide`,
`build: finalize release metadata and publish workflow`. Full pre-completion
checklist + the build/install smoke test. Push, verify CI green. Then **hand
off**: post the exact `git tag` / release-create commands from `RELEASING.md`
for the maintainer to run. DO NOT merge or tag without explicit sign-off.

## Definition of done

- Version is `1.0.0`; CHANGELOG `[1.0.0]` section written with migration guide.
- Release metadata (classifiers, python-requires, URLs) production-ready.
- Built wheel installs clean in a fresh venv and computes a chart.
- `publish.yml` matches `RELEASING.md`; no token stored.
- Maintainer hand-off checklist posted. CI green. Awaiting human tag push.
