# Task v1.0-06: Documentation — Sphinx/ReadTheDocs, docstrings, README accuracy

## Context

Read `CLAUDE.md` fully (Code-style clause: *"Docstrings: Google style, required
on all public functions and classes"*). Read `README.md`, `docs/source/` (if it
exists), `docs/HOW-IT-WORKS.md`, `docs/API-STABILITY.md` (from v1.0-05), and the
Phase-1 doc-candidates note in `docs/CONTRIBUTION-PLAN.md` ("Set up Sphinx docs
and ReadTheDocs"). Confirm v1.0-05 has merged.

## Why this task exists

A 1.0 needs published, browsable API docs and a README that is exactly true. Two
gaps:

1. **No generated API docs.** Sphinx + ReadTheDocs was a Phase-1 candidate that
   never landed. The public surface is now frozen (v1.0-05) — the right moment
   to auto-document it.
2. **README drift risk.** The README carries a PyPI badge and a version badge;
   claims like coverage %, module counts, and "complete Vedic subsystem" must
   match reality (some vedic pieces are explicitly *simplified/heuristic* and
   should say so where the README implies completeness).

## Design decisions (already made)

- **Sphinx with `autodoc` + `napoleon`** (Google-style docstrings), sourced
  from the frozen `__all__`. Config under `docs/source/`; build to
  `docs/_build/` (gitignored). Add a `.readthedocs.yaml` at repo root pinning
  the Python version and the `docs` extra.
- **Docstring coverage pass:** every public symbol in `docs/API-STABILITY.md`
  gets a Google-style docstring (Args/Returns/Raises). Use an interrogate-style
  check or a simple script to find gaps; fill them. Internal helpers are exempt.
- **README is verified, not just edited:** the quick-start snippet is already
  tested (v1.0-05). For every *quantitative* claim (coverage, test count,
  module count, LOC), either regenerate it from the current tree or soften it to
  a non-brittle phrasing. For every *completeness* claim about vedic features,
  cross-check `CLAUDE.md`'s deferred/heuristic notes and add the honest caveat.
- **Docs extra:** add a `docs` optional-dependency group (`sphinx`,
  `sphinx-rtd-theme` or `furo`, `myst-parser` if Markdown docs are included) to
  `pyproject.toml`, pinned like the dev tooling from v1.0-01.

## Task scope

1. `pyproject.toml`: add a pinned `docs` extra.
2. `docs/source/conf.py`, `index.rst`/`index.md`, and per-module `automodule`
   stubs generated from `__all__`. `.readthedocs.yaml` at repo root.
3. Docstring gap-fill across the public surface (Google style).
4. README accuracy pass — quantitative claims regenerated; vedic completeness
   claims caveated to match `CLAUDE.md`.
5. Add a `make docs` / `docs/Makefile` target (one likely already exists —
   verify it builds clean with **no warnings**, since RTD treats warnings as
   build noise).

## Tests

- `sphinx-build -W docs/source docs/_build` succeeds with **zero warnings**
  (the `-W` turns warnings into errors — this is the doc "test").
- A docstring-coverage check reports 100% on the public surface (script it, or
  add `interrogate` to the docs extra and set a threshold).
- The full suite (including the v1.0-05 README quick-start test) still passes.

## Out of scope

- Hosting/enabling the ReadTheDocs project in the RTD dashboard (a dashboard
  action, not a repo change) — leave a note in `docs/RELEASING.md`.
- Tutorial/narrative docs beyond what already exists in `docs/` — API reference
  + accurate README is the 1.0 bar; deeper guides go in `docs/IDEAS.md`.
- Changing any public symbol (frozen in v1.0-05).

## Process

Branch `v1.0-06-docs-sphinx-readme`. Commits:
`build: add pinned docs extra`,
`docs: scaffold Sphinx + ReadTheDocs config`,
`docs: fill public-API docstring gaps`,
`docs: reconcile README quantitative and completeness claims`, then the
checklist `docs:` commit. Full pre-completion checklist plus the
`sphinx-build -W` gate. Push, verify CI, DO NOT merge.

## Definition of done

- `sphinx-build -W` builds the API reference cleanly from `__all__`.
- `.readthedocs.yaml` present; `docs` extra pinned.
- 100% docstring coverage on the public surface.
- README claims verified; vedic completeness honestly caveated.
- Checklist passes; CI green.
