# Task v1.0-03: Remove the `flatlib/` compatibility package

## Context

Read `CLAUDE.md` fully. Read the `flatlib/` directory (it is a thin
compatibility shim added in Task 005 that re-exports `mayaastrolib` and emits a
`DeprecationWarning` on import), `tests/test_compat.py`, and the pyproject
package-discovery config. Confirm v1.0-02 has merged and the suite is green.

## Why this task exists

`flatlib/` exists so people who installed the fork as a drop-in `flatlib`
replacement keep working through the 0.x line. `CLAUDE.md` records it as
*"will be removed in 1.0"*. A 1.0 that still ships a second importable
top-level package under an old name is carrying migration scaffolding into its
stable era. Time to drop it.

## Design decisions (already made)

- **Delete the `flatlib/` directory entirely.** `import flatlib` should fail
  with a normal `ModuleNotFoundError` at 1.0, not a deprecation warning.
- **Package discovery:** ensure `pyproject.toml` (setuptools `packages` /
  `find` config) no longer includes or globs `flatlib`. The build must produce
  a wheel that contains **only** `mayaastrolib`.
- **Tests:** `tests/test_compat.py` (the shim's own tests — importing flatlib,
  asserting the warning, asserting re-export identity) is deleted. If it also
  contains `_compat.py` property-migration tests, split those out and keep them
  — only the flatlib-shim assertions go.
- **`MANIFEST.in` / packaging metadata:** remove any `flatlib`-specific lines.

## Task scope

1. `rm -r flatlib/`.
2. `pyproject.toml`: drop `flatlib` from package discovery so only
   `mayaastrolib` (and subpackages) is built.
3. `MANIFEST.in`: remove flatlib references, if any.
4. Delete `tests/test_compat.py`'s flatlib-shim assertions (keep any genuine
   `_compat` property-migration tests, relocating them if needed).
5. Grep the whole repo for `flatlib` — update or remove every remaining
   reference in `docs/`, `README.md`, `recipes/`, and prompts. (Historical
   mentions in `CHANGELOG.md` and old `prompts/task-005-rename.md` stay as
   history; forward-looking "you can import flatlib" claims go.)

## Tests

- `python -c "import flatlib"` raises `ModuleNotFoundError`.
- `python -c "import mayaastrolib; from mayaastrolib.chart import Chart"` works.
- `python -m build` produces a wheel; inspecting it (`unzip -l dist/*.whl`)
  shows **no** `flatlib/` entries.
- Full suite passes with the shim and its tests gone.

## Out of scope

- Removing `mayaastrolib/_compat.py` (internal property-migration helper — not
  a 1.0 removal).
- Rewriting `CHANGELOG.md` history that mentions the rename (that is a record of
  what happened).

## Process

Branch `v1.0-03-remove-flatlib-shim`. Commits:
`feat!: remove the flatlib compatibility package`,
`build: drop flatlib from package discovery`,
`docs: purge forward-looking flatlib references; update CHANGELOG/PROJECT-LOG`.
Full pre-completion checklist **plus** a build check (`python -m build` +
wheel-contents inspection). Push, verify CI, DO NOT merge.

## Definition of done

- `flatlib/` gone; `import flatlib` is a plain `ModuleNotFoundError`.
- Built wheel contains only `mayaastrolib`.
- No forward-looking flatlib references remain in docs/README/recipes.
- `CHANGELOG.md` "Removed (BREAKING)" notes the shim removal with the
  `from flatlib import X` → `from mayaastrolib import X` migration line.
- Checklist passes; CI green.
