## Context

"deferred" caveat), `mayaastrolib/_compat.py`, `mayaastrolib/object.py`,
`mayaastrolib/chart.py`, and `mayaastrolib/aspects.py`. Read the two already-

## Why this task exists

The package ships `py.typed`, which promises consumers a fully typed API. Three
core modules — `aspects.py`, `chart.py`, `object.py` — are still untyped. They
were deferred every prior pass for one concrete reason: their
`self.__dict__.update(...)` construction (`Aspect` / `AspectObject`) and the
`_compat`-decorated dynamic attributes (`Object` / `House`) mean that simply
adding signatures surfaces ~30 mypy "has no attribute" errors. This is the
deferred **refactor**, not a quick annotation pass — and it is the last thing
standing between the code and an honest `py.typed`.

## Design decisions (already made)

- **`from __future__ import annotations`** at the top of each module (matches
  the typed exemplars).
- **Kill the dynamic-attribute opacity with explicit class-level annotations.**
  For `Object`, `House`, `Aspect`, `AspectObject`, declare every attribute the
  class actually carries as a class-level annotation (`id: str`, `lon: float`,
  `lonspeed: float | None`, `sign: str`, ...). This is what teaches mypy the
  attributes exist without changing runtime behaviour.
- **Restructure `Aspect.__init__`** so it assigns named attributes explicitly
  instead of `self.__dict__.update(...)`. Behaviour identical; mypy can now see
  the fields. Do the same for `AspectObject` if it uses the same pattern.
- **`_compat` decorator:** give it a precise type (a generic/`ParamSpec`
  signature or a `Protocol`) so decorated methods keep their annotations rather
  than degrading to `Any`. If a fully-precise type is impractical, a documented
  narrow `# type: ignore[...]` at the decorator definition (not scattered at
  every call site) is acceptable — record the reasoning in `PROJECT-LOG.md`.
- **No behaviour change.** This is types + a mechanical `__init__` restructure
  only. Existing tests must pass untouched; the golden tests are the guardrail.

## Tests

- `mypy mayaastrolib/` stays at (or below) the documented baseline — the ~30
  dynamic-attribute errors are **gone**, and no new errors are introduced. If
  the pyswisseph-no-stubs errors remain, they are the known baseline; document
  the exact count in `PROJECT-LOG.md`.
- The **entire existing suite passes unchanged** — no test edits should be
  needed (types are erased at runtime). If a test needs changing, that signals
  an accidental behaviour change: stop and fix the code, not the test.
- Add nothing to golden tests; they already pin the behaviour that must not
  move.

## Out of scope

- Typing internal/underscore helpers beyond what's needed to clear the errors.
- Any API or behaviour change (renames, new params, semantics).
- Removing `_compat.py` (still needed).
