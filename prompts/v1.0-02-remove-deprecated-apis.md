# Task v1.0-02: Remove the function/method-level deprecated APIs

## Context

Read `CLAUDE.md` fully, `docs/PROPERTY-MIGRATION.md`, and `mayaastrolib/_compat.py`.
Confirm v1.0-01 has merged and the suite is green. Every symbol below was shipped
with a `DeprecationWarning` that explicitly says *"will be removed in version 1.0"* —
this task honours that promise.

## Why this task exists

A 1.0 must not carry the deprecation debt it told users would be gone by 1.0.
Leaving these in makes the version number a lie and keeps two code paths alive
for every affected feature.

## Inventory (verified deprecation sites — remove all)

| Symbol | File | Replacement (already exists) |
|---|---|---|
| `getAspectOrSentinel()` | `mayaastrolib/aspects.py:~268` | `getAspect()` (returns `None`) |
| `setTerms()` | `mayaastrolib/dignities/essential.py:~71` | `terms_variant=` kwarg |
| `setFaces()` | `mayaastrolib/dignities/essential.py:~50` | `faces_variant=` kwarg |
| `Object.relocate()` | `mayaastrolib/object.py:~150` | `Object.with_longitude()` |
| `Object.antiscia()` / `Object.cantiscia()` | `mayaastrolib/object.py:~188` | `Object.antiscion()` / `cantiscion()` |
| `predictives.profections.compute()` | `mayaastrolib/predictives/profections.py:~26` | `Chart.profected(target_date=...)` |
| `tools.arabicparts.getPart(ID, chart)` | `mayaastrolib/tools/arabicparts.py:~193` | `Chart.arabicPart(ID)` |
| `House._OFFSET` alias | `mayaastrolib/object.py` (House) | `House._CUSP_TOLERANCE_DEG` |

> Before deleting, **re-grep** for each symbol across `mayaastrolib/`, `tests/`,
> `docs/`, `recipes/`, and `README.md` — the line numbers above may have
> drifted, and there must be zero remaining internal callers after removal.

**Do NOT remove the `flatlib/` package here** — that is the separate, larger
task v1.0-03. This task is method/function-level removals only. `_compat.py`
itself stays (it still backs the `House`/`Object` property migration); only the
deprecated *method-style* shims that name a 1.0 removal go away.

## Task scope

1. Delete each deprecated symbol and its `DeprecationWarning` plumbing.
2. Update every internal caller to the replacement (there should be few or
   none — these were already migrated).
3. Update the tests: delete the tests that assert *"the deprecated path emits a
   warning"* (e.g. in `test_aspect_api.py`, `test_dignities_thread_safety.py`,
   `test_predictives_profections.py`, `test_tools_arabicparts.py`,
   `test_with_longitude.py`, `test_antiscia.py`). Keep — and where needed add —
   tests that assert the **replacement** behaves correctly.
4. Update `docs/PROPERTY-MIGRATION.md` and any doc that references a removed
   symbol.

## Tests

- The full suite passes with the deprecated symbols gone.
- `grep -rn` for each removed symbol name across `mayaastrolib/`, `tests/`,
  `docs/`, `recipes/`, `README.md` returns nothing (except the `CHANGELOG`
  removal note).
- No `DeprecationWarning` referencing "version 1.0" remains for these symbols
  (`pytest -W error::DeprecationWarning` on the affected modules is clean).

## Out of scope

- Removing the `flatlib/` compat package (task v1.0-03).
- Removing `_compat.py` or the `House`/`Object` property-access migration —
  those are not slated for 1.0 removal.
- Any new feature work.

## Process

Branch `v1.0-02-remove-deprecated-apis`. One commit per logically-grouped
removal is fine, e.g. `feat!: remove getAspectOrSentinel (use getAspect)`,
`feat!: remove setTerms/setFaces (use *_variant kwargs)`, etc. Use the
conventional-commit `!` breaking marker. Final `docs:` commit updates
`CHANGELOG.md` **"Removed (BREAKING)"** section (list every symbol + its
replacement), `PROJECT-LOG.md`, and `CLAUDE.md` deprecation notes. Full
pre-completion checklist. Push, verify CI, DO NOT merge.

## Definition of done

- All eight deprecated symbols removed; no internal callers remain.
- Warning-assertion tests removed; replacement behaviour still covered.
- `CHANGELOG.md` records every removal with its migration path.
- Checklist passes; CI green.
