# Road to 1.0 — prompt index

This is the ordered backlog that takes `mayaastrolib` from **0.3.0** to a
**1.0.0** release. Each `v1.0-NN-*.md` file is a self-contained task prompt,
written to be run in a **single Claude Code CLI session**, one after another.

Run them **in order** — later prompts assume earlier ones have merged. Feed a
prompt with e.g.:

```sh
claude -p "$(cat prompts/v1.0-01-release-hygiene.md)"
```

or paste its contents into an interactive session. Do **one task per session**
(the `CLAUDE.md` working agreement), finish the pre-completion checklist, merge,
then start the next.

## What "1.0.0" means for this project

1.0 is the point where the **public API is frozen and honest**: every
deprecated shim is gone, the type hints are complete enough to back `py.typed`,
the documented surface is the real surface, and a clean clone builds and tests
green with pinned tooling. It is **not** gated on 100% Vedic feature depth —
the optional feature-depth prompt is clearly marked and can ship in a later
minor.

## Ground rules (apply to every prompt)

- Read `CLAUDE.md` fully first. It OVERRIDES defaults.
- One task per session. Branch per task (`v1.0-NN-slug`). Never push to `main`.
- Do **not** modify tests to make them pass — fix the code. If a test is
  genuinely wrong, explain in `PROJECT-LOG.md`.
- Pre-completion checklist, in order: `ruff format --check .` · `ruff check .`
  · `mypy mayaastrolib/` · `pytest -x` · `pytest --cov=mayaastrolib
  --cov-fail-under=80` · update `docs/PROJECT-LOG.md` · update `CHANGELOG.md`.
- Anything a prompt uncovers but doesn't fix goes in `docs/IDEAS.md`, not scope
  creep.

## Breaking-change note

Prompts 02 and 03 remove public API. That is the whole point of a major
version — but it means **1.0.0 is a breaking release**. Every removal must land
in the `CHANGELOG.md` "Removed (BREAKING)" section for 1.0.0 with the exact
replacement, so downstream users have a migration path.
