# Task v1.0-01: Release hygiene — pinned tooling & hermetic tests

## Context

Read `CLAUDE.md` fully. Read `pyproject.toml` (the `[project.optional-dependencies]`
`dev` extras and the `[tool.ruff]` / `[tool.mypy]` config), `docs/RUFF-DEBT.md`,
`tests/test_concurrency.py`, and `mayaastrolib/ephem/swe.py` (the `sweFixedStar`
path around `fixstar2_ut`). Confirm the suite runs.

## Why this task exists

A clean-clone reviewer cannot currently reproduce the project's own quality
claims. Two concrete gaps, both observed on a fresh checkout:

1. **Unpinned dev tooling.** `dev` extras list bare `"ruff"` and `"mypy"`. A
   newer `ruff` than the one the code was last formatted with reports ~20 files
   as needing reformatting, so `ruff format --check .` **fails** on a fresh
   install even though `CLAUDE.md` says it passes. "Green on the maintainer's
   machine" is not green.
2. **Non-hermetic tests.** Four tests in `tests/test_concurrency.py` (the
   fixed-star and full-report ones) hard-fail with
   `swisseph.Error: could not find star name algol` when the Swiss Ephemeris
   fixed-star data file (`sefstars.txt`) is not present. They read as bugs but
   are environmental — the data file simply is not vendored or guarded.

Both must be closed before a 1.0 that anyone can build and trust.

## Design decisions (already made)

- **Pin the dev tooling** to specific versions in `pyproject.toml` dev extras:
  `ruff==<current>` and `mypy==<current>` (use the versions you actually run in
  this task; record them). Pinning tooling is standard for reproducible lint —
  it is not a runtime dep, so it does not constrain library consumers.
- **Re-settle the format** once, with the pinned `ruff`: run `ruff format .`
  and commit the resulting churn as a single mechanical "style" commit,
  separate from any behavioural change. After this, `ruff format --check .`
  must pass with the pinned version.
- **Make the fixed-star tests hermetic** by *guarding*, not by vendoring the
  Swiss Ephemeris star catalogue (it carries the GPL/commercial Swiss Ephemeris
  licensing question — out of scope here). Detect at runtime whether the star
  catalogue is available; if not, `pytest.skip(...)` those tests with a clear
  reason. A skipped test is honest; a hard failure that looks like a code bug
  is not.
  - Add a small helper (e.g. a module-scope `pytest` fixture or a
    `_fixstar_data_available()` probe that does one guarded lookup and caches
    the boolean) and `@pytest.mark.skipif(...)` / `pytest.skip(...)` the four
    affected tests.
  - Do **not** weaken what the tests assert when data *is* present — only skip
    when it is genuinely absent.

## Task scope

- `pyproject.toml`: pin `ruff` and `mypy` in the `dev` extras.
- Whole tree: `ruff format .` with the pinned ruff; commit the churn separately.
- `tests/test_concurrency.py` (and any other test that reaches
  `getFixedStar`): add the skip-guard so the suite is green with or without the
  star catalogue present.
- Optionally add a one-line note to `docs/RUFF-DEBT.md` recording the pinned
  ruff version and why.

## Tests

- `pytest -x` is green on a checkout **without** `sefstars.txt` (the four
  concurrency tests skip, they do not fail).
- If you can obtain the star data locally, confirm the four tests still **run
  and pass** when it is present (the guard skips only on genuine absence).
- `ruff format --check .` passes with the pinned ruff.
- No assertion in any test was weakened.

## Out of scope

- Vendoring or redistributing the Swiss Ephemeris star catalogue (licensing).
- Any UP031 / ruff-lint debt beyond what `ruff format` itself changes — leave
  `docs/RUFF-DEBT.md` items as-is.
- Pinning the *runtime* dep (`pyswisseph`) more tightly — separate concern.

## Process

Branch `v1.0-01-release-hygiene`. Suggested commits:
`build: pin ruff and mypy in dev extras`,
`style: reformat with pinned ruff` (mechanical, no logic change),
`test: skip fixed-star tests when the swisseph star catalogue is absent`,
`docs: update CHANGELOG, PROJECT-LOG for v1.0-01`.
Full pre-completion checklist. Push, verify CI green, DO NOT merge to main.

## Definition of done

- `ruff format --check .`, `ruff check .`, `mypy mayaastrolib/` all pass.
- `pytest -x` is green on a clean clone with **no** star catalogue present.
- Tooling versions are pinned; the format churn is isolated in its own commit.
- `CHANGELOG.md` + `docs/PROJECT-LOG.md` updated. CI green.
